## 1. Executive Summary

A comprehensive audit was conducted across all 97+ codebase files, 15 documentation items, database schemas, deployment configurations, and runtime dependencies of the **WE WERE HERE** project.

### Key Audit Findings:
1. **The application has successfully transitioned into a modern multi-event platform.** The FastAPI Python backend is the sole active production runtime, verified by VPS deployment scripts (`wwh-deploy.sh`), systemd configurations, and 135 passing pytest tests.
2. **`server.js` is legacy code and is not used in production.** It cannot run the modern multi-event database or the disposable camera / storage / support features.
3. **The true design system is "Gothic + Cute" (`third-shahrivar`),** implemented in `assets/wwh-theme.css`. The conflicting teal Survey/Form Builder files in `design-system/we-were-here/` were auto-generated by an external generator tool and must be archived.
4. **`design-system/we-were-here/ticket-field-layout.json` is an active runtime dependency.** It must NOT be treated as disposable documentation, as it is dynamically loaded by `backend/app/services/ticket_layout.py`.
5. **No active runtime files in `assets/` are unused.** Every single CSS and JS file under `assets/` is loaded by one or more public pages or test suites.
6. **Large non-runtime clutter exists in the root directory:** ~41 MB of unreferenced debug screenshots (`admin-big.png`, `admin-test.png`) and development probe scripts/fixtures should be relocated into structured developer tooling directories.

## 2. Answers to the Three Core Questions

### Question 1: Do we really have two backends? What is the production boundary?

**Answer:** **No, there is only ONE active production backend: FastAPI (Python).**

| Criterion | FastAPI (`backend/app/main.py`) | Legacy Node.js (`server.js`) |
|---|---|---|
| **Production Execution** | Defined in `wewerehere.service`, started by Uvicorn on port 5173 | Not executed anywhere on VPS |
| **Deployment Automation** | Built into `wwh-deploy.sh` (virtualenv, pip, systemd restart) | Ignored by `wwh-deploy.sh` |
| **npm scripts** | `npm run dev` and `npm start` launch FastAPI via Uvicorn | Only `npm run dev:node` launches Node |
| **Database Architecture** | 22 multi-event relational tables (Events, Orders, Storage, Memories) | 4 flat single-event tables (no `events` table) |
| **Feature Coverage** | 100% (Events, SVG/PNG tickets, Memories, Storage Engine, SMS, Support) | ~20% (obsolete single-event order prototype) |
| **Compatibility Status** | Current Production Core | Historical Legacy / Rollback Reference |

#### The Migration Boundary:
- `server.js` is retained for historical safety and reference.
- `backend/scripts/migrate_legacy.py` is the one-way bridge: `backend/app/main.py:_maybe_migrate_legacy()` checks SQLite upon startup; if the database has old Node tables but lacks the `events` table, it automatically runs `migrate_legacy.py` to upgrade the schema.
- Once migrated, `migrate_legacy.py` is never called again during normal operations.

### Question 2: Do we have conflicting design systems? Which is authoritative?

**Answer:** **Yes, there was a documentation contradiction, but the code reality is 100% unified under "Gothic + Cute".**

1. **The Authoritative Design System:**
   - Location: `design-system/third-shahrivar/MASTER.md`
   - Philosophy: "Gothic + Cute" (Dark aesthetic, high contrast, pure white on `#0A0A0B`, cute pink-red accent `#D43F5A`, Vazirmatn Persian typography, JetBrains Mono numbers).
   - Implementation: `assets/wwh-theme.css`, `assets/wwh-shell.css`, and all HTML pages (`index.html`, `track.html`, `episodes.html`, `memories.html`, `support.html`, `admin.html`).

2. **The Spurious Documentation:**
   - Location: `design-system/we-were-here/MASTER.md` (and related `pages/episodes.md`, `pages/index.md`).
   - What happened: On 2026-10-11, an automated tool generated a design template assuming the application was a "Survey / Form Builder" with a light teal (`#0D9488`) color palette and `Atkinson Hyperlegible` font.
   - Evidence of conflict: In `design-system/we-were-here/pages/admin.md`, the developer had to explicitly write:
     > *"Overrides MASTER.md for the live admin shell in admin.html. The production admin UI is dark (WWH night tokens), not the light teal survey palette in Master... Do not introduce Master light teal cards into admin."*

3. **The Hidden Runtime JSON in the Design Folder:**
   - `design-system/we-were-here/ticket-field-layout.json` contains the exact pixel coordinates for `ticket-a.svg` and `ticket-b.svg`.
   - **`backend/app/services/ticket_layout.py:13` directly imports and parses this JSON file at runtime.**
   - Moving or deleting `design-system/` without updating `ticket_layout.py` would crash ticket rendering in production!

### Question 3: Do unused/temporary files impact runtime website performance?

**Answer:** **Repository clutter does NOT directly slow down browser page loads, but specific runtime resource loading patterns DO affect end-user experience.**

We must strictly distinguish between two categories:

#### Category A: Repository Clutter (Zero impact on web visitors)
- Files like `admin-big.png` (28.3 MB) and `admin-test.png` (12.5 MB) in the repository root are never requested by client browsers.
- Scratch scripts (`backend/scripts/_*`), test probes (`_probe.html`, `_track_probe.json`), and database dumps (`backend/_events.json`) sit idle on the disk.
- **Their actual impact:** They inflate `git clone` download times, bloat repository backups, and increase `rsync` sync duration if not excluded. They do not degrade page speed.

#### Category B: Real Runtime Performance Bottlenecks (Direct impact on web visitors)
1. **External Google Fonts Dependency:**
   - `index.html` connects to `fonts.googleapis.com` and `fonts.gstatic.com` to download Vazirmatn and JetBrains Mono.
   - For users in Iran, Google Fonts often suffers from high latency, packet loss, or CDN filtering, causing visible layout shifts (CLS) or flash of invisible text (FOIT).
   - *Optimization:* The repository ALREADY bundles `assets/fonts/Vazirmatn-Regular.ttf` for CairoSVG. Serving this font locally via CSS `@font-face` eliminates third-party network blocking.
2. **Multiple Canvas Animation Loops on Mobile:**
   - `index.html` concurrently runs three animation mechanisms: `wwh-fish.js` (requestAnimationFrame canvas drawing), `wwh-atmosphere.js` (particle canvas rendering), and `wwh-spotlight.js` (mouse radial glow).
   - On low-end mobile devices, multiple canvas contexts running continuous rAF loops cause frame drops and battery drain.
   - *Optimization:* Pause off-screen or unneeded canvas animation when scrolled out of view, or when device prefers reduced motion / battery saver.
3. **CDN Dependencies in `admin.html`:**
   - The admin panel loads Flatpickr, QRCode, and Chart.js from `cdn.jsdelivr.net`.
   - If jsDelivr is blocked or slow on the admin's network, the panel stalls.
   - *Optimization:* Bundle or vendor these small libraries locally in `assets/vendor/`.
4. **SQLite Database Concurrency & Locking:**
   - `backend/app/db.py` creates the SQLite engine with default `journal_mode=DELETE`.
   - During concurrent write bursts (e.g. dozens of guests submitting orders or uploading memories at an event), write locks can block concurrent read queries.
   - *Optimization:* Enable WAL mode (`PRAGMA journal_mode=WAL;`) and set a busy timeout (`PRAGMA busy_timeout=5000;`) in SQLite connection pragma.

In the local repository working copy, an extensive **Media Storage Manager** subsystem was recently added (uncommitted changes):
- New database models in `backend/app/models.py`: `StorageProvider`, `EventStorageConfig`, `EventStorageFolder`, `MediaAsset`, `UploadReservation`, `StorageUsageSnapshot`, `StorageRoutingLog`.
- New service layer in `backend/app/services/storage/`:
  - `files_ir_adapter.py`: Files.ir official cloud storage integration.
  - `s3_adapter.py`: S3-compatible object storage integration.
  - `local_adapter.py`: Local filesystem fallback.
  - `routing_manager.py`: Event-level storage routing and quota failover.
  - `upload_manager.py`: Multipart & chunked upload coordinator.
- New admin router in `backend/app/routers/storage_admin.py`.
- 18 dedicated tests in `backend/tests/test_storage_manager.py`, all passing.
- New chunked upload widget in `assets/wwh-uploader.js` and `assets/wwh-uploader.css`.

**Audit Verdict on Storage:** This subsystem is cleanly decoupled, adheres to clean architecture principles, has complete test coverage, and correctly handles cloud failover. It should be committed as an atomic unit rather than mixed with repository refactoring.
